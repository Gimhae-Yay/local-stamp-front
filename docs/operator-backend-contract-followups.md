# 운영자 프론트엔드 Backend 계약 후속 메모

작성일: 2026-08-20

## 목적

운영자 프론트엔드를 우선 완료하기 위해 현재 Backend 조회 계약에서 제공하지 않는 값을 프론트엔드가 임의 생성하지 않고 제한적으로 보완한다. 아래 호환 처리는 임시이며 Backend 계약이 보강되면 제거한다.

## Backend 후속 변경

### 1. 콘텐츠 수정 금액

- 현재: `GET /api/v1/operator/contents/{contentId}` 응답에 `reservationPrice`가 없다.
- 문제: 콘텐츠 수정·수정본 제출 요청에는 `reservationPrice`가 필수다.
- 제안: 콘텐츠 상세 응답에 `reservationPrice: number`를 추가한다.
- 프론트 임시 처리: 이 브라우저에서 마지막으로 성공한 등록·수정 요청의 금액만 사용자·콘텐츠별로 저장해 다음 수정 화면에 복원한다. 저장값이 없으면 재입력한다.

### 2. 미션 수정 제목

- 현재: `GET /api/v1/operator/missions/{missionId}` 응답에 `title`이 없다.
- 문제: 미션 수정 요청에는 `title`이 필수다.
- 제안: 미션 상세 응답에 `title: string`을 추가한다.
- 프론트 임시 처리: 이 브라우저에서 마지막으로 성공한 생성·수정 요청의 제목만 사용자·미션별로 저장해 복원한다. 저장값이 없으면 재입력한다.

### 3. 운영자 스탬프북 조회

- 현재: 운영자용 스탬프북 생성·수정·게시 API는 있지만 목록·상세 조회 API가 없다.
- 문제: 새로고침 또는 다른 기기 접속 시 생성한 스탬프북의 ID와 상태를 복원할 수 없다.
- 제안:
  - `GET /api/v1/operator/stampbooks`
  - `GET /api/v1/operator/stampbooks/{stampbookId}`
- 프론트 임시 처리: 마지막 입력값과 생성·수정·게시 응답을 사용자별 브라우저 저장소에 보관한다. 서버의 현재 상태를 보장하지 않으며 다른 브라우저와 동기화되지 않는다.

### 4. 운영자 세션 조회

- 현재: 콘텐츠 상세 응답에 세션이 없고 공개 세션 API는 공개 가능한 예정 세션만 제공한다.
- 문제: 심사 대기·반려·취소·종료 세션과 정원·체크인 시간을 운영자 화면에서 조회할 수 없다.
- 제안: `GET /api/v1/operator/contents/{contentId}/sessions`를 추가하고 세션 ID, 상태, 시작·종료 시각, 정원, 체크인 시작·종료 시각을 반환한다.
- 프론트 임시 처리: 공개 세션 API가 반환하는 범위만 표시하고 미조회 데이터를 만들지 않는다.

### 5. 운영자 표시 이름

- 현재: `GET /api/v1/me`에서 운영자 표시 이름을 제공하지 않는다.
- 제안: 필요 시 `displayName`을 추가한다.
- 프론트 임시 처리: 사용자 ID를 표시한다.

## 임시 저장 정책

- 키 접두사: `local-stamp:operator-compat:v1`
- 사용자 ID를 키에 포함해 같은 브라우저의 운영자 계정 간 값을 분리한다.
- 인증 토큰, 개인정보, 예약자 정보는 저장하지 않는다.
- API 요청이 성공한 값과 운영자가 작성 중인 스탬프북 구성만 저장한다.
- 저장소 오류나 손상된 JSON은 화면 동작을 막지 않고 무시한다.

## 로컬 대표 이미지 업로드

- 로컬 Backend의 `FakeImageStorageClient`는 presigned 응답 생성 시 객체 메타데이터만 등록하며 실제 이미지 바이트를 받는 PUT 엔드포인트는 제공하지 않는다.
- 프론트는 `localhost`, `127.0.0.1`, `[::1]`의 `/local-image-storage/` URL만 로컬 fake 저장소로 판별해 PUT을 생략한다.
- S3 또는 그 밖의 URL에서는 presigned 응답의 헤더를 사용한 실제 PUT 업로드를 그대로 수행한다.

## Backend 보강 후 제거 체크리스트

1. 새 응답 필드 및 신규 API의 Backend 계약 테스트를 추가한다.
2. 프론트 타입과 API 함수를 실제 응답에 맞춘다.
3. `operatorCompatStorage.ts` 사용 지점을 서버 응답으로 교체한다.
4. 화면의 임시 저장·재입력·조회 제한 안내를 제거한다.
5. 기존 브라우저 호환 키를 한 번 정리하고 관련 테스트를 삭제한다.
