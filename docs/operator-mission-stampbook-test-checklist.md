# 운영자 지역 미션·스탬프북 기능 테스트 체크리스트

## 테스트 결과 기록 기준

- 결과는 `PASS`, `FAIL`, `BLOCKED` 중 하나로 기록한다.
- API 요청의 Method, URL, Query Parameter, Request Body를 확인한다.
- HTTP 상태 코드와 응답 내용을 기록한다.
- API 응답과 화면에 표시된 값이 일치하는지 확인한다.
- 실패 시 재현 절차, 오류 메시지, 콘솔 오류와 스크린샷을 첨부한다.

---

# 14. 지역 미션

## 목록·페이지네이션

- [ ] 미션 화면 진입 시 `GET /api/v1/operator/missions?page=0&size=20`가 호출된다.
- [ ] 기본 요청의 `page=0`, `size=20`이 적용된다.
- [ ] 로그인한 운영자가 담당하는 미션만 표시된다.
- [ ] API 응답의 미션 내용과 상태가 목록에 정확히 표시된다.
- [ ] 다음·이전 페이지 이동 시 요청의 `page`가 변경된다.
- [ ] 페이지 이동 후 해당 페이지의 데이터가 표시된다.
- [ ] 페이지 크기 변경 기능이 있다면 요청의 `size`가 변경된다.

## 상태 필터

- [ ] 전체 상태 조회가 가능하다.
- [ ] `DRAFT` 필터 선택 시 아래 요청이 호출된다.

```http
GET /api/v1/operator/missions?status=DRAFT&page=0&size=20
```

- [ ] 필터 변경 시 `page=0`으로 초기화된다.
- [ ] 선택한 상태에 해당하는 미션만 표시된다.
- [ ] API 응답과 화면의 표시 결과가 일치한다.

## 생성

- [ ] 미션 생성 시 `POST /api/v1/operator/missions`가 호출된다.
- [ ] 입력한 값이 Request Body에 정확히 포함된다.
- [ ] 필수값 누락 및 잘못된 입력에 Validation이 동작한다.
- [ ] 생성 성공 후 신규 미션이 목록에 반영된다.
- [ ] 생성 실패 시 서버 오류가 화면에 표시된다.

## 상세

- [ ] 상세 화면 진입 시 `GET /api/v1/operator/missions/{missionId}`가 호출된다.
- [ ] API 응답의 상세 데이터와 화면 표시 값이 일치한다.
- [ ] 존재하지 않거나 접근 권한이 없는 미션의 오류를 정상 처리한다.

## 수정

- [ ] 수정 시 `PATCH /api/v1/operator/missions/{missionId}`가 호출된다.
- [ ] 변경한 값이 Request Body에 정확히 포함된다.
- [ ] 수정 성공 후 변경 내용이 상세와 목록에 반영된다.
- [ ] 수정 가능한 상태에서만 수정 버튼과 UI가 제공된다.
- [ ] 수정 불가능한 상태에서 직접 수정 URL로 접근해도 수정할 수 없다.
- [ ] 수정 불가능 상태의 서버 오류가 화면에 표시된다.

## 검토 요청

- [ ] 검토 요청 시 `POST /api/v1/operator/missions/{missionId}/submit`이 호출된다.
- [ ] 요청 성공 후 미션 상태가 변경된다.
- [ ] 상태 변경 후 가능한 액션 버튼이 올바르게 갱신된다.
- [ ] 연속 클릭으로 중복 요청이 발생하지 않는다.
- [ ] 이미 요청했거나 잘못된 상태에서 재요청한 경우 오류를 정상 처리한다.

## 조기 종료

- [ ] 종료 실행 전에 확인 팝업 또는 확인 UI가 표시된다.
- [ ] 확인을 취소하면 종료 API가 호출되지 않는다.
- [ ] 종료 확인 시 `POST /api/v1/operator/missions/{missionId}/end`가 호출된다.
- [ ] 종료 성공 후 상태가 종료 상태로 변경된다.
- [ ] 종료된 미션에서 수정·검토 요청·종료 버튼이 제한된다.
- [ ] 종료된 미션의 직접 수정 URL 접근도 제한된다.
- [ ] 중복 종료 요청 또는 잘못된 상태 전이 오류를 정상 처리한다.
